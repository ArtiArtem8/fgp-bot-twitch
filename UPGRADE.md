# Обновление установленного FGPbot на Windows

Целевой путь из предоставленных логов: `E:\Python\fgp-bot-twitch`.
Архив содержит верхнюю папку `fgp-bot-twitch`, внутри которой лежит новый `main.py`.

## 1. Остановить старую версию и сохранить личные файлы

Останови старый процесс бота. На время обновления не запускай его повторно через
автозагрузку. Сделай **локальную приватную** резервную копию `.env`, папки `data`
целиком и исходников. Если присутствуют `tokens.db-wal` / `tokens.db-shm`, сохраняй
вместе с базой; копировать работающую SQLite просто как один файл ненадёжно.

Не отправляй резервную копию в чат или публичный репозиторий: там могут быть токены.

## 2. Заменить исходники

Скопируй содержимое папки `fgp-bot-twitch` из ZIP в существующую папку проекта,
подтвердив замену исходников. Не создавай лишнюю вложенность
`fgp-bot-twitch\fgp-bot-twitch`.

В ZIP нет `.env`, `data`, `.venv`, `.git`: личная конфигурация, база и история Git
не подменяются. Старый путь `main.py` и название `runtwitchbot.bat` сохранены.
Настройку автозапуска с этим путём менять обычно не нужно.

Старые `components/`, `config.py`, `utils.py` и каталог `test/` новый `main.py` не
импортирует. Их можно убрать из рабочей папки после резервного копирования.
**Особенно убери `test/main.py` и `test/test_vpn.py`: в исходном архиве там были
жёстко записанные секреты.** Новый каталог автоматических тестов называется `tests/`,
с буквой `s`: не удаляй его.

Если старые файлы отслеживаются Git, их удаление оформляется как обычное удаление
исходников. Новый архив не включает raw diff со старыми строками секретов.

## 3. Заменить раскрытые секреты

В логе за **23 сентября 2026, 16:55:01** остались незамаскированные Client Secret и
refresh token. Есть также секреты в экспериментальных исходниках.

Заменить Client Secret приложения в Twitch Developer Console, затем записать
новое значение локально в `TWITCH_BOT_APP_CLIENT_SECRET` своего `.env`.
Отозвать прежнее разрешение приложения у аккаунта бота и пройти авторизацию
заново. Одна лишь выдача ещё одного токена или удаление сообщения с логом не
является надёжной заменой отзыва раскрытых разрешений.

Client ID и числовые ID пользователей сами по себе секретами не являются;
менять их из-за этой утечки не требуется. Если раскрывались токены других
аккаунтов, отозвать и перевыдать соответствующие разрешения тоже.

## 4. Установить зависимости и авторизовать бота

Для обновления runtime до Python 3.14.x сначала останови работающий бот, затем
запусти `setup.bat` с установленным `uv`: он пересоздаст `.venv` при смене версии
Python. Существующие `.env` и `data/tokens.db` сохраняются; только из-за смены
Python повторная авторизация не требуется.

Открой PowerShell в папке проекта:

```powershell
Set-Location 'E:\Python\fgp-bot-twitch'
.\setup.bat
.\selftest.bat
.\authorize-bot.bat
```

Остановка на ошибке setup/selftest — повод исправить её до включения автозапуска.
Если старое окружение повреждено, после остановки бота переименуй `.venv` в
`.venv-old` и запусти setup повторно. Не переносить старые секретосодержащие
экспериментальные скрипты в новое окружение.

В браузере войти **в аккаунт бота** с ID `1293258394`. Redirect приложения должен
быть `http://localhost:4343/oauth/callback` либо точно совпадающим значением
`TWITCH_REDIRECT_URI` из `.env`. Старый процесс TwitchIO должен быть остановлен:
он тоже мог занимать порт 4343.

Токен стримера `494679299` не нужен для чтения чата и обычных ответов.
Ранее заданный `TWITCH_OWNER_ID=494679299` продолжает определять целевой канал,
если `TWITCH_CHANNEL_ID` отдельно не задан.

## 5. Запустить и проверить

```powershell
.\runtwitchbot.bat
```

В другом окне PowerShell:

```powershell
Set-Location 'E:\Python\fgp-bot-twitch'
.\status.bat
.\check-chat.bat
```

`status` ничего не публикует. **`check-chat` публикует одно диагностическое сообщение**
и ожидает его обратную доставку. `PASS` подтверждает путь отправки/приёма в момент
проверки. `READY` без сквозной проверки означает готовый транспорт, не доказанную
доставку. Не нужно самому заходить в Twitch и писать команду зрителем.

При ошибке сохрани вывод `status --json`, `doctor` и новые очищенные логи.
Не прикладывай `.env` и `tokens.db`. Права и API музыкального провайдера проверяются
отдельно от основной сквозной проверки.

## Откат

Остановить новую версию и вернуть прежние исходники из локальной копии. Дополнительные
таблицы SQLite не мешают исходной схеме; возвращать старую базу обычно не требуется.
**Не возвращать скомпрометированные Client Secret и токены.** Откат к старому коду
также возвращает исходные дефекты и опасное логирование, поэтому годится только
как временная диагностическая мера.
