# Обновление установленного FGPbot на Windows

## Сохранить рабочие данные

Останови бот и временно отключи его автозапуск. Сделай приватную резервную копию
`.env` и всей папки `data/`. Если рядом с `tokens.db` есть файлы `-wal` и `-shm`,
сохраняй их вместе с базой. Не публикуй резервную копию: в ней есть токены.

Исходники и `uv.lock` можно обновить без замены `.env` и `data/tokens.db`.
Схема существующих таблиц `tokens` и `messages` сохраняется. Client ID, ID канала,
OAuth scopes и рабочие токены менять ради обновления кода или Python не требуется.
Повторная авторизация нужна только при отсутствующем, отозванном или недостаточно
разрешённом токене либо после раскрытия секрета.

## Обновить окружение

Проект требует Python `>=3.14,<3.15` и `uv`. Из папки проекта запусти:

```powershell
.\setup.bat
.\selftest.bat
```

`setup.bat` синхронизирует только runtime зависимости через
`uv sync --locked --no-dev`. Оно не запускается при обычном старте бота.
Если прежнее `.venv` повреждено, останови бот, переименуй его в `.venv-old`
и повтори установку. `selftest.bat` использует локальные серверы и временные базы,
не рабочие токены.

## Запустить и проверить

```powershell
.\runtwitchbot.bat
```

В другом окне PowerShell запусти `status.bat`. `READY` означает, что сейчас готовы
авторизация, WebSocket, подписка и обработчик. При желании запусти `check-chat.bat`:
он публикует **одно видимое диагностическое сообщение** и ждёт его EventSub echo.
`doctor` проверяет авторизацию и подписку без отправки сообщения и без refresh.

При ошибке сохраняй очищенные логи и вывод `status --json`/`doctor`, не прикладывая
`.env` или `tokens.db`. Если секрет раскрыт, отзови и замени его у провайдера;
простое удаление файла не отменяет уже выданный доступ.
