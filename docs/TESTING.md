# Проверка сборки

## Дополнительный прогон при установке на Windows — 23 сентября 2026

После установки архива выполнены `setup.bat` и `selftest.bat` на Windows,
Python 3.12.1, aiohttp 3.14.3, python-dotenv 1.2.3: **117 тестов, OK**.
Исправлено закрытие SQLite-соединения в фикстуре теста миграции: контекстный
менеджер `sqlite3.Connection` завершает транзакцию, но не закрывает соединение;
на Windows это мешало удалить временную базу. Используется `contextlib.closing`.
Рабочее ядро из архива для этого исправления не менялось.

В отдельном временном Git-репозитории проверен pre-commit hook: безопасный
коммит проходит, многострочный Client Secret и добавление `.env` блокируются.
Использованы только синтетические значения. Зависимости зафиксированы в `uv.lock`.

После запуска новой версии read-only `doctor` подтвердил действующую авторизацию,
наличие нужных chat scopes и одну подписку `channel.chat.message` на текущей
WebSocket-сессии. Статус процесса — `READY`. Access token восстановлен через
refresh и сохранён. `check-chat --send` не запускался: доставка исходящего
сообщения этим прогоном не подтверждена. Эти результаты относятся к моменту
установки и не гарантируют последующую доступность сервиса.

Ниже сохранён исходный отчёт поставщика архива; его показатели покрытия относятся
к исходному прогону Linux. Покрытие повторно не измерялось.

Особенно важные регрессии: нерабочий токен владельца больше не блокирует чат бота;
новая OAuth-пара сохраняется даже при отказе следующей валидации; HTTP 200 с
`is_sent=false` не считается отправкой; текущая серверная подписка проверяется,
а её исчезновение вызывает восстановление; совпадение `message_id` для echo
обязательно, в том числе при получении echo раньше ответа POST.

## Границы подтверждения

Все сетевые интеграции в тестах направлены на **127.0.0.1 / localhost** с
синтетическими учётными данными. Ни секреты исходника, ни пользовательские `.env`
и база не используются. Twitch и музыкальный провайдер в ходе тестов не вызывались.

Параметры прокси HTTP/WS проверены тестами вызовов, но реальный CONNECT/TLS через
Hiddify на Windows здесь не воспроизводился. BAT-файлы, Windows-ветка файловой
блокировки, автозагрузка, сон/пробуждение, реальные OAuth-разрешения, политика
модерации канала и актуальный контракт Trula требуют проверки на рабочей машине.

Никаких заявлений о фактическом уменьшении RAM/CPU не делается: сравнительный
бенчмарк старой и новой версии на одной машине не проводился.

## После установки на Windows

Сначала `setup.bat`, затем `selftest.bat`. После замены секретов и авторизации —
`runtwitchbot.bat`. Для тихой проверки — `status.bat`. Для подтверждения основного
реального пути — `check-chat.bat`: он публикует одно сообщение с одноразовым
маркером. Успешный локальный selftest не заменяет эту live-проверку.
