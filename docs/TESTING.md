# Проверка проекта

Проект требует Python `>=3.14,<3.15`. Тесты используют `unittest` и локальные
HTTP/WebSocket-серверы с синтетическими данными. Они не обращаются к Twitch,
Trula, пользовательскому `.env` или `data/tokens.db`.

## Воспроизводимые команды

```powershell
uv sync --locked
just test
just cov
just ci
uv run python main.py selftest
```

`just test` запускает все тесты. `just cov` повторяет их с покрытием и проверяет
кроссплатформенные минимумы: 86,5% общего покрытия и 76% ветвей. `just ci`
дополнительно запускает Ruff format/lint, `ty`, `deptry`, Tach, `uv audit`, Gitleaks для истории Git,
`actionlint` и `zizmor`. Текущий результат смотрите в CI или получайте этими
командами: консольный вывод и таблицы покрытия в репозитории не сохраняются.

GitHub Actions отдельно запускает runtime/type-check на Windows и Ubuntu. Статические,
dependency- и security-проверки выполняются один раз на Ubuntu. Небольшая разница
покрытия между ОС ожидаема из-за платформенных ветвей; gate задаёт общий нижний
порог для обеих CI-сред.

Проверки валидируют используемые поля OAuth, Helix и EventSub через
`msgspec.Struct`; неизвестные поля wire payload допустимы. Отдельные тесты
проверяют OAuth refresh, WebSocket reconnect/handoff, подтверждение chat echo,
ограниченную очередь и локальный журнал сообщений.

При `FGP_LOG_CHAT=true` обычные сообщения зрителей и команды сохраняются в
`messages`; повторный `message_id` не создаёт второй строки. Сообщения самого бота
и события из другого source broadcaster Shared Chat не записываются. Ошибка записи
журнала не останавливает обработку команды; retention удаляет только записи старше
настроенного срока.

## Проверка установленного бота

`setup.bat` использует `uv sync --locked --no-dev` для установки только runtime
зависимостей. Затем `selftest.bat` можно запустить без настоящих токенов.

Для работающего бота `status.bat` читает локальный статус без сетевого запроса.
`check-chat.bat` отправляет одно видимое диагностическое сообщение в Twitch и ждёт
его EventSub echo. `READY` подтверждает текущую готовность транспорта, а успешный
`check-chat` — доставку одного конкретного сообщения. Тесты не проверяют поведение
машины после сна и реальный контракт музыкального сервиса.

## Результат проверки 24 сентября 2026

На Windows с Python 3.14: **134 теста, OK**; общее покрытие **87,1%**, покрытие
ветвей **76,7–76,9%** в двух прогонах. `just check`, `just ci` и `selftest`
прошли. Это датированный результат, а не замена текущей проверке CI.
