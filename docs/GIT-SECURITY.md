# Защита секретов в Git

`.env`, базы SQLite с токенами, журналы и резервные копии исключены через
`.gitignore`. Рабочие секреты должны оставаться только в локальной конфигурации
и базе. В `.env.example` используются заглушки.

Перед коммитами выполняется Gitleaks с маскированием найденных значений.
Помимо стандартных правил проверяются многострочные литералы Client Secret
и случайно добавленные приватные файлы.

Для новой рабочей копии установите Gitleaks, добавьте его в PATH и включите hook:

```text
git config core.hooksPath .githooks
```

Ручная проверка всей истории:

```text
gitleaks git . --log-opts="--all --full-history" --redact=100 --ignore-gitleaks-allow
```

Hook действует локально, не устанавливается автоматически при клонировании
и не гарантирует обнаружения любого секрета. Не обходите его через `--no-verify`.
Если действующий секрет раскрыт в логе, файле или сообщении, его необходимо
отозвать и заменить у провайдера; удаление файла не отзывает выданные права.

При обновлении 23 сентября 2026 года проверены все 25 исходных коммитов,
а также все локальные объекты Git на известные значения из конфигурации,
баз токенов и экспериментальных скриптов. Совпадений не найдено. Поэтому
история сохранена без переписывания. Незакоммиченные экспериментальные скрипты
с литералами секретов убраны из рабочей папки в приватную резервную копию.
