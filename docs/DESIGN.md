# Устройство бота

`main.py` передаёт управление в `fgpbot.cli`. Конфигурация и пути загружаются
из папки проекта. `Application` связывает SQLite, Twitch API, EventSub,
обработчики команд и запись состояния.

| Модуль | Ответственность |
| --- | --- |
| `config` | Настройки и пути |
| `wire` | Проверка входящих JSON через `msgspec` |
| `network` | HTTP, прокси, тайм-ауты и ограниченные повторы |
| `tokens` | Валидация, обновление и кэш OAuth-токенов |
| `twitch` | Используемые методы Helix |
| `eventsub` | WebSocket, переподключение и перенос сессии |
| `commands` | Разбор команд и ответы в чат |
| `storage` | Транзакции SQLite |
| `health` | Состояние процесса и атомарная запись `status.json` |
| `security` | Очистка секретов в логах |

## Приём и обработка

Сообщения зрителей сохраняются в SQLite до проверки ограничений команд.
Запрет `DELETE` из `messages` закреплён триггером. Ошибка записи останавливает
приём событий. Служебные маркеры дедупликации и диагностики очищаются отдельно.

Команды попадают в ограниченную очередь с четырьмя обработчиками. Один зритель
может занимать только один слот. Cooldown считается от поступления команды;
устаревшая команда пропускается, сохраняясь в истории.

Критические задачи принадлежат `asyncio.TaskGroup`. Необработанная ошибка
останавливает остальные задачи. При отмене запись в фоне завершается до
освобождения блокировок и выхода из процесса.

## Сеть и авторизация

HTTP, OAuth callback и EventSub используют одну `aiohttp`-сессию с явно заданным
прокси. При переносе EventSub старый сокет читается до welcome нового;
перенесённые подписки повторно не создаются.

Чат использует токен бота. Дополнительный токен владельца нужен для `followage`.
Обновлённая пара access/refresh сохраняется до следующего запроса. SQL
compare-and-swap защищает одновременную ручную авторизацию от фонового refresh.

GET имеет ограниченные повторы. POST после сетевого сбоя не повторяется;
полученный 401 допускает одну попытку с обновлённой авторизацией.
Маркер дедупликации сохраняется до отправки ответа: сбой между этими действиями
может потерять ответ, зато не воспроизводит его после перезапуска.

## Диагностика

Готовность авторизации, транспорта и обработчиков отслеживается отдельно.
`check-chat` создаёт локальную заявку, отправляет одно сообщение и сверяет
EventSub echo. `status` читает сохранённый снимок; `doctor` проверяет настройки
и доступ к API. Секреты остаются в локальных `.env` и SQLite.
